# Practical **[60 marks]**

> [!NOTE]
> You may ask Redbrick admins, previous webmasters, or other nerds for help with this section

The RB committee needs to keep attendance of the number of people that attend the events they host, but instead of having mehow go and ask everyone for their name, what we should do is make a website where people can submit their name, and the event they are attending. The committee can then view the submissions in a nice format with the:

- Username
- Event Name
- Time of submission

As well as having an overall count of the number of people attending each event.

## Part 1: Websites & APIs **[40 marks]**

### Setup
1. Fork and clone the [webmaster exam 2026 agm starter pack](https://github.com/arisamiga/webmaster-exam-2026-agm-starter-pack).
    - Make sure the repository is private and invite `arisamiga` as a collaborator.
2. Get familiar with the code.
    - There is a backend API written with [FastAPI](https://fastapi.tiangolo.com/).
    - The backend API has three endpoints:
        - `/newevent` which accepts POST requests
        - `/submit` which accepts POST requests
        - `/view` which accepts GET requests
    - You can view full documentation at <http://localhost:8000/docs> when you run the backend.

### Task 1 - SQL

Finish writing the callbacks for the API endpoints.
- `/newevent` should create a new event and return whether it was successful.
- `/submit` should insert a person's attendance for an existing event and return whether it was successful.
- `/view` should get the attendance data for the event and return it, or `None` if the event does not exist.

### Task 2 - JS & CSS

Create a frontend using a framework of your choice. Please use `Tailwind CSS` for styling.

It should have three pages: one to create an event, one to submit attendance, and one to view event attendance.

#### Create Event Page

Contains a form with the following input:
- Event Name

On submission, this form should send a POST request to `/newevent` on the backend with the form input as the request body.

#### Submit Attendance Page

Contains a form with the following inputs:
- Username
- Event Name

On submission, this form should send a POST request to `/submit` on the backend with the form inputs as the request body.

#### View Attendance Page

This page should:
- take a URL parameter, e.g. `/view/{event}`
- send a GET request to `/view` on the backend using that event value
- display the attendance data, or an error message if the event does not exist

### Task 3 - Docker
1. Create [Dockerfiles](https://fastapi.tiangolo.com/deployment/docker/#dockerfile) for both the backend and frontend.
2. Create a [docker compose](https://docs.docker.com/compose/gettingstarted) file which defines services for the backend and frontend.
    - It should build the images using your Dockerfiles
    - Don't forget to mount the database file as a volume!
